# Security audit, 2026-10-26

This audit reviewed the Go server, web client, Electron client, Android client and
native bridges, database access, media pipeline, integrations, deployment and
release tooling, and dependency manifests. `CLAUDE.md` was read first. Work was
performed by one agent, without subagents. Changes are local and have not been
deployed or pushed. The pre-existing edit in `tools/advert.py` is unrelated.

The review traced security boundaries and searched source across the project. It
is not a claim that every line of generated assets or vendored code was manually
reviewed, or a proof that no vulnerabilities remain. Live infrastructure, production
data, credentials and external paid services were not used as attack targets.


The expanded validation below covers findings 1–29. The owner authorized a new
private desktop update-signing key after the original could not be found. Copies
were installed in private storage on the build server and Mac. This was the only
remote write; no release or deployment ran.

## Findings fixed

### 1. Concurrent initial registrations could create multiple Developers

**High, privilege escalation during instance setup.** `handleRegister` decided
the administrator flag from a user count read before the inserting transaction.
Requests that observed the same empty instance could each retain that flag.

`Store.CreateRegisteredUser` now makes the bootstrap decision in the inserting
transaction. SQLite's writer serialization and a PostgreSQL transaction advisory
lock protect the same decision. The configured initial administrator exception is
checked there too. General `CreateUser` callers retain their existing behavior.

The HTTP regression coordinates competing requests at the writer pool. Running it
with the original handler through a Go source overlay created three administrators;
the fixed implementation creates one. A store regression also checks stale
administrator candidates directly.

### 2. Attachment metadata could traverse Android's private cache paths

**Medium, private file disclosure with user interaction.** A sender controls the
decrypted attachment's `blob_id`. Unlike thumbnail ids, full attachment ids were
accepted as arbitrary strings. Android used this string in `File(cacheDir, id)`
and returned an existing nonempty file before any download or decryption.
Traversal strings could therefore select other readable application files, which
could be displayed or copied when the attachment was opened or saved. No automatic
remote exfiltration was demonstrated.

Both clients now require 1 to 20 ASCII digits in attachment metadata. Android also
validates at the media-cache filesystem boundary. Regression cases include parent
segments, absolute paths, encoded traversal, backslashes, queries and fragments.
The web's existing valid test fixtures now use actual numeric blob-id shapes.

### 3. Android's exported share target accepted private file URIs

**Medium, local application confused-deputy attack.** Another application could
explicitly send Nexa an `ACTION_SEND` intent with a `file:` URI. Nexa's content
resolver would open it with Nexa's filesystem permissions and stage it for sending.
This required a local malicious application and a subsequent user send action.

The external share boundary now accepts external `content:` authorities only,
rejects Nexa's own FileProvider authority (including Android user-id prefixes),
and caps incoming files at the existing ten-file composer limit. A pure policy
regression covers these URI classes. Authority normalization follows
[Android's provider lookup](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-29/+/refs/heads/main/android/content/ContentProvider.java).

### 4. GIF work limits were checked after full decompression

**High, server availability.** Both cropping and animated variants called
`gif.DecodeAll` before checking the decoded animation's budget. A compressed GIF
could allocate all its frame buffers before being refused. The two-worker variant
limit did not bound the memory consumed by each decoded input.

`internal/media/gif_budget.go` now walks GIF block headers and sub-block lengths
before decoding, validating frame rectangles, frame count and canvas work. Crop
limits remain 600 frames and 150 Mi pixels. Animated variants also enforce a
600-frame limit and retain their existing work limit and original-file fallback.
The decoder still validates pixel data after the preflight passes.

Regressions use tiny compressed structures that exceed the budget and invalid or
truncated descriptors. They prove rejection before LZW decoding or rendering.

### 5. Concurrent upload bodies bypassed quota and temporary-disk accounting

**High, server availability and quota bypass.** Single-request uploads checked
quota before receiving their bodies. Several unfinished requests could each spend
the same remaining allowance. Resumable chunks were staged before the transfer
lock, allowing duplicate offsets to create arbitrary concurrent temporary copies.

Admission now serializes quota checks and reserves arriving bodies until the
database accounts for them. Encrypted channel files, notes, sounds and private
support uploads use this admission path. New resumable uploads use it too. Staged
chunks have separate disk accounting and limits of sixteen globally and two per
transfer; a retry can still complete while an older body stalls. Filesystem-space
lookup failures refuse admission.

Before-fix regressions accepted an extra upload with HTTP 201 despite exhausted
quota, and a third duplicate chunk with HTTP 200. The fixed routes answer 507 and
429 respectively. The existing stalled-request/retry regression still passes.
Reservations are process-local, matching the documented single-chatd deployment.

### 6. The bot gateway bypassed unauthenticated connection admission

**Medium, unauthenticated availability attack.** `/bot-gateway` upgraded sockets
and started their workers before applying the waiting-connection limits used by
`/gateway`. An attacker needed no bot account to hold those resources until the
identify timeout.

`gateway.Hub.AdmitWaiting` now shares the existing admission budget with the bot
gateway. Reservations are released on successful identify/resume and every failure
path. A real-WebSocket regression verifies that unidentified bot connections count
toward the same limit as account connections and that closing one releases space.

### 7. Guests bypassed channel Video permission in SFU requests

**Medium, authorization bypass.** `mayStream` gave guests the constant maximum
guest permissions instead of the current channel's `@everyone` permissions.
Additionally, ICE restart republished existing video without repeating the Video
check. A custom client could use these routes after video was denied.

Guest video authorization now uses the channel's effective guest permissions.
Permission lookup errors deny access. ICE restart repeats the same check. The
existing publish and subscribe paths use this shared decision. A fake-SFU HTTP
regression publishes while allowed, denies Video, then verifies that the old
session is retired (HTTP 409) and a fresh forbidden publication returns HTTP 403.

### 8. IPv6 address rotation bypassed the daily signup allowance

**Medium, abuse prevention bypass.** The registration attempt limit used the
IPv6 /64 rate key, but the successful-signup limit used the entire address. A
client could rotate addresses within its assigned prefix to obtain fresh daily
allowances, subject to the other registration checks.

Successful signups now use `auth.RateKey` too. A regression submits three distinct
addresses in one /64 and verifies that the third signup is refused.

### 9. IPv6 translation addresses could conceal nonpublic IPv4 destinations

**Conditional SSRF hardening.** The address guard recognized IPv4-mapped IPv6,
but accepted standard NAT64 and 6to4 addresses embedding loopback, private or
metadata IPv4 addresses. Exploitation requires a deployment or egress network that
routes the corresponding translation/tunnel addresses; this was not tested against
production infrastructure.

The embedded IPv4 address is now checked for standard NAT64 and 6to4 addresses.
Public embedded destinations remain usable. Local-use translation, Teredo and
IPv4-compatible ranges are refused. Unit tests cover loopback, metadata, private
and public embedded addresses.

### 10. Known dependency advisories

The initial full npm audits reported 7 affected package entries in the web tree,
10 in desktop, and 10 in the video tooling. These counts include transitive and
development packages and are not counts of remotely exploitable production bugs.
The Go toolchain scan also found reachable standard-library advisories, and the
installed Python font tooling included an affected Brotli decoder.

Updates include Go 1.27.3, `golang.org/x/net` 0.60.0, Electron 44.9.3, React Router
7.18.4, Vite 6.4.5, Vitest 4.1.12 and patched transitive npm packages. Desktop's

The shipped license catalogue was regenerated; its test now scopes a dependency
notice separately from Nexa's own always-visible MIT notice.

### 11. New sends and edits could keep using an obsolete conversation key

**High within the removal/privacy threat model.** The old crypto audit's stale-epoch
finding was still present: the API refused future epochs but accepted every older
one, and both clients selected the newest key they happened to hold. Edits could
also keep using a server-wide key after their channel became private. An old key
holder who obtained the resulting ciphertext could still decrypt this new content;
normal API membership checks already refused removed members access to messages.

Both clients now ask for the current epoch before sending/editing. New encrypted
message writes and edits recheck the epoch under the epoch-creation transaction
lock, and edits use the channel's current conversation. HTTP/store/race regressions
cover stale sends, stale edits and edits after a channel becomes private. This is
not forward secrecy or protection against a current member deliberately leaking keys.

### 12. Plain exports included the app-lock password verifier

**Medium, local/export disclosure.** Both web and Android exports included the
synchronized `appLock` policy, including the salt, KDF parameters and verifier.
Both now omit it, with archive/policy regressions. Web verifier comparison also
uses the existing byte comparison helper. JavaScript is not formally constant-time.

### 13. A forwarded-address fallback let a proxy caller choose its rate key

**Conditional rate-limit bypass.** `ClientIP` trusted the first `X-Forwarded-For`
entry when a loopback proxy omitted `CF-Connecting-IP`. That first entry can be
client-supplied. The fallback is removed; Cloudflare addresses are parsed and
normalized, and malformed values fall back to the actual peer. Gateway tests now
simulate the documented Cloudflare header instead of the removed fallback.

### 14. Overlong usernames became persistent limiter keys

**Low, resource hardening.** Login and recovery accepted names up to their request
body limit before creating per-name limiter entries; KDF lookup also lacked the
registration length bound. Normalized names longer than 32 bytes are now refused
before these operations. Password/recovery failures retain their timing floor.

### 15. Guests could repeatedly mint paid-service TURN credentials

**Medium, upstream resource abuse.** Guest ICE requests deliberately bypassed the
member cache. A guest now reuses its own credential only until a minute before it
expires. Parallel requests share one mint. A fake-upstream regression checks
concurrent/sequential reuse and renewal after expiry; no real paid service was called.

### 16. Release installers could be served while only partly copied

**Medium, release integrity/availability.** Desktop artifacts and blockmaps were
copied directly to public final names. They now become visible by atomic rename
after a successful copy. An interrupted copy preserves an existing artifact.
Publishing also refuses a stale platform feed naming a different version before
writing release files. Tests use temporary directories only. Android's current
release tool already performs temporary-file replacement.

### 17. Packaged desktop apps still honored development environment switches

**Low, local configuration hardening.** Test profile paths, capture overrides and
simulated installer/update decisions affected installed apps. A shared `testHook`
now returns no override when packaged. Logging's intentional `EVILION_DEBUG`
switch remains. Packaged/unpackaged regressions and the desktop suite pass.

### 18. Locked subchats could still be deleted before unlocking

**Medium, authorization inconsistency/data loss.** The special channel-delete
dispatch checked participation and management rights but skipped the password
gate. Deletion now requires the same session unlock as other protected operations.
The password-gate regression tests a locked participant's delete request. The
documented encrypted realtime/screen-lock model is unchanged.

### 19. Android sign-out retained notification and cache state

**Medium, disclosure across local account boundaries.** Session reset now cancels
pending notification posts, checks the account generation when publishing, clears
message history and tagged system notifications,
resets navigation/layers and clears media. Cache names also include the numeric
account id, preventing the next account from hitting an earlier account's file.
The connection service's untagged foreground notification is preserved.

### 20. Whole encrypted chunks could be removed without a chunk-tag failure

**Medium, attachment integrity.** Per-chunk authentication cannot prove file
completeness. Android depended on HTTP length when available, while a whole-frame
prefix still opened when the response omitted that length. Full-file attachment
readers now check the message-authenticated plaintext size and canonical chunk
count on both clients. New regressions remove a complete final chunk while leaving
every retained tag valid. This preserves the existing ECF1 format.

### 21. An unopenable stored key grant prevented any honest replacement

**Medium, availability against another conversation member.** Grant insertion
keeps the first row. Re-requesting did not remove an invalid wrapper, so holders
never saw the recipient as missing that epoch. An entitled recipient can now
submit `bad_epoch` and the exact `bad_wrapped_key` to `POST /keys/request`; only
its own matching row is removed before holders are notified. Both clients report
unopenable wrappers. A mismatched/stale report cannot remove a replacement.

HTTP and client regressions cover this repair. A malicious authorized member can
still sabotage availability or distribute an authenticated wrong root; the server
cannot determine the truth of an encrypted root. This fix does not claim otherwise.

### 22. Native Android frame crypto used hand-written AES and GHASH

**Implementation hardening against local side channels.** Secret-indexed AES
lookup tables were replaced by RustCrypto AES-GCM through a narrow native bridge.
Keys, authenticated headers, AES-256-GCM parameters and frame format are unchanged.
NIST/tamper/in-place tests pass. Ten audio, VP8 and H.264 vectors produce identical
bytes in the old Android backend, the replacement and actual WebCrypto, with
cross-decryption. This is not a formal side-channel proof for every CPU.

### 23. Sparse call epochs could overwrite another retained frame key

**Availability during key changes.** Epochs differing by 256 collided locally.
Both clients now retain full epoch numbers and try the bounded matching candidate
set using GCM authentication. The transmitted index remains compatible. The native
regression failed before this fix and passes afterward. Browser and guest-key
regressions cover the collision too.

### 24. SFU moderation and usage admission trusted client behavior

**Authorization and upstream resource abuse.** Server mute/deafen, Speak and Video
changes retire the provider session and increment `sfu_generation`. Both clients
rebuild with permitted tracks. Publish/pull/restart enforce audio restrictions,
and in-flight negotiations repeat authorization. Per-user provider mutations are
serialized, duplicate publications are refused, and repeated pulls reuse their
existing mid. Camera/share off now closes its publication.

Accounting follows actual publications and confirmed closures, including
per-track provider errors. Failed closures remain charged; retired sessions retry
transient closure failures. Screen estimates use the supported maximum instead of
a client's low declared bitrate. Metering remains an estimate, not a provider
billing cap. Provider outages can delay forced closure. Fake-provider HTTP/race
and browser-transport unmute/reconnect tests pass. Older clients may need to rejoin
after forced retirement; newer clients recover automatically.

### 25. SFU kind labels were not bound to negotiated media types

**Video-permission bypass.** A client could label negotiated video as audio.
Publication now checks unambiguous SDP media-section/mid associations and refuses
duplicate mids. ICE restarts must name the exact recorded publication mid and its
matching negotiated media type. Parser and HTTP-route regressions pass.

### 26. Slow request bodies outlived header/idle deadlines

JSON bodies now have a 30-second read deadline, and other bodies fifteen minutes.
Raw-TCP regressions check both classes. The deadline remains through net/http's
post-handler body drain. JSON/error responses also get a restrictive default CSP;
document handlers retain their explicit document policy.

### 27. Public fetches allowed arbitrary destination ports

The public-address guard now permits only HTTP 80 and HTTPS 443, with dialing
independently restricted to those ports. Address and redirect checks remain.
Public-host port 22/8080/8443 and scheme-mismatch regressions pass. No real network
services were scanned.

### 28. Activity links hid destinations behind custom labels

Both clients show the canonical host below labels/buttons and ask the user to
review the full URL before opening it. Only HTTP/HTTPS without userinfo becomes
actionable. Desktop/phone browser and Android Dark/Light/Onyx checks exercised a
misleading label using a reserved `.invalid` domain.

### 29. Desktop updates lacked independent release authentication

Every new desktop updater verifies exact feed bytes against a pinned Ed25519 key
before parsing checksums. Signatures also bind their platform feed names. Bounded
reads and absent/tampered/wrong-key/wrong-feed tests cover the macOS updater and a
custom electron-updater provider for Windows/AppImage.

After searches found no original private key, the owner explicitly authorized a
new desktop key. Private copies outside both checkouts have owner-only permissions
and matching public fingerprints. Only its public key enters Git. Publishing
refuses missing/mismatched signing material before exposing artifacts. Dedicated
`signed-latest*.yml` feeds preserve legacy unsigned feeds. Signature sidecars use
no-cache, rather than immutable caching.

Version 1.2.8 introduces this trust anchor. Once it is published, older desktop
clients loading the current web app get a mandatory manual-installer screen,
even if their updater reports a staged update. There is no Later/Restart shortcut
through the unsigned updater. Installed/offline old code cannot be remotely made
to enforce a new trust anchor. The first installer remains a trusted manual
bootstrap. No release ran and no users have been forced to update by this work.

### Additional requested bug: homepage demo account prompt

Modal initial/restored focus uses `preventScroll`. Desktop/phone browser checks
preserve the outer scroll offset on opening/closing the embedded account prompt.
The original jump was not reproduced in this Chromium build. The unguarded focus
mechanism was corrected and covered by a focus-options regression.

## Verification and limits

- The pre-change check passed. The expanded `tools/check.sh` passed Go build/vet/tests,
  web typecheck and all 296 files/2,836 tests, scratch build/size gates, desktop
  typecheck/tests/bundle and repository/i18n checks. The subsequent Mac download
  bound passed the full desktop suite again: 18 files, 67 tests, plus typecheck
  and bundle. Four release-publisher regressions pass with ephemeral test keys.
- Focused HTTP, WebSocket, store, GIF and address-guard tests include before-fix
  source-overlay reproductions. Authentication/upload/bot tests passed under the
  race detector. Epoch, grant repair, proxy, subchat and TURN race checks passed.
  The final SFU/voice/realtime race run passed in 42.9 seconds. A broad earlier
  API race run reached the ten-minute suite timeout while progressing; no full
  API race-suite pass is claimed.
- The Android debug APK built for every configured ABI. All 168 unit tests ran:
  160 passed and eight skipped, with no failures. One stale URL expectation was
  refreshed against current Node and Chromium, which both reject that hostname
  just as Android does. The parser was not weakened and the input corpus stayed
  unchanged. The SDK is Homebrew's android-commandlinetools installation.
- Native Rust NIST/tamper/in-place tests pass. Ten audio/VP8/H.264 vectors match
  byte-for-byte between old Android, replacement Android and actual WebCrypto,
  with cross-decryption/tamper checks. A retained host test also checks colliding
  call epochs and fails on the old local key-selection behavior.
- Muted emulator checks covered encrypted messages, image decryption, sign-out
  notification/cache removal, and refusing a private-file share intent. Activity
  destination review was checked in Dark, Light and Onyx. Screenshots were inspected.
- Desktop/phone browser checks at 1366x768 and 411x914 passed sign-in, routing,
  encrypted send, upload and image decryption on the isolated preview. Activity
  host/review and homepage demo scroll checks passed. Manual-upgrade screens were
  exercised for Windows/macOS/Linux at both sizes, with browser/new-client controls.
- Full npm audits reported zero advisories in all three package trees.
  `govulncheck ./...` found zero reachable vulnerabilities and zero affected
  imported packages. OSV queries covered 101 explicitly versioned Rust/Maven
  packages, 205 resolved Android runtime versions, 13 installed Python packages,
  and the new frame backend's 19 crates. No vulnerability advisory affected the
  new frame closure. The `smallstr` unmaintained notice and unused OpenPGP module
  notice are distinguished from demonstrated, reachable vulnerabilities.
- Repository privacy and Gitleaks checks cover the staged work and reachable
  public Git history. Neither private key is in the public checkout. Android
  private-key entries open on both machines and their certificates match the
  published Android certificate. No Android release key was changed.
- The historical index reconciles 116 security/related findings and inventories
  all 1,297 report records. It explicitly distinguishes fixed code, accepted
  behavior, open design limits and unverified historical nonsecurity observations.
- Edge TLS, real third-party call-provider behavior, production rollout and formal
  cryptographic correctness were not independently verified. The usage meter is
  approximate; provider outages can delay SFU retirement. A full compromise of
  a build host holding the signing key can forge releases. First-contact identity
  trust, message-v1 replay/revision binding, shared call-key sender authentication,
  and local/offline storage threats remain documented design/protocol limits.

No production build, service restart, database migration, release publication or
Git push was performed. Existing installations need an authorized deployment and
client releases. Desktop clients below 1.2.8 then need a trusted manual installer
once; future desktop updates authenticate the signed feeds.
