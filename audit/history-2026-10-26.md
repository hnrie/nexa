# Historical audit reconciliation, 2026-10-26

**The historical audits are not fully closed.** The old `open` markers and the
round-one review are historical records, not a reliable statement about current code.
This reconciliation checks every explicitly security-labelled finding from both
rounds, all 24 crypto findings, all 23 server-security findings and all 25
desktop/release findings. Related privacy and authorization findings are included.

The inventory contains 720 round-one findings and 490 round-two findings.
A further 87 product/design sections are indexed for completeness. These counts
are records, not unique vulnerabilities: the rounds overlap. The 13 lost
`SCORE-001` through `SCORE-013` findings have no report text to revalidate.

Security dispositions below come from current source and focused checks. A
nonsecurity item labelled **Not revalidated** is not claimed fixed merely because
the current test suite passes. This audit does not certify every historical
layout, translation, performance or product-parity observation.

## Remaining risks that must not be called fixed

- Desktop update authentication now has a new trust anchor; old installed clients require a trusted manual installer before signed updates apply.
- Message replay/revision/metadata binding and call-frame sender/version guarantees need protocol work.
- Native AES uses RustCrypto now; whole-device timing behavior still depends on the hardware and runtime.
- First-contact/server membership trust, default browser storage and offline passcode guessing remain design limits.
- SFU policy is enforced and existing sessions retired, but provider outages can delay closure and usage remains an estimate.
- Aggregate object caps and temporary per-account login lockout remain open or partly mitigated; activity disclosure and default-port restrictions are now fixed.
- Signing keys have private copies on Mac and server. Independent encrypted/offsite recovery, edge TLS and deployed-version rollout still require verification.

See [the security audit](security-2026-10-26.md) for fixes and final validation.
