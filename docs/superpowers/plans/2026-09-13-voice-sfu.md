# Evilion Chat — Voice through Cloudflare Realtime SFU Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Every voice and video call goes through Cloudflare Realtime SFU (with Cloudflare TURN for blocked networks), so nobody in a call learns another person's IP address, while calls stay end-to-end encrypted and within Cloudflare's free allowance.

**Architecture:** chatd keeps the Realtime app secret and becomes the SFU's signalling proxy: it creates one SFU session per call device, publishes that device's tracks, and lets a device subscribe only to the tracks of people in its own call. Track names never leave the server; voice states carry only which kinds a participant publishes. The browser holds one RTCPeerConnection to Cloudflare and encrypts every audio and video frame with a key derived from the conversation's root key (RTCRtpScriptTransform, with createEncodedStreams as the fallback), so the SFU forwards frames it cannot read. A server-side meter estimates the month's SFU egress from what each device pulls and at what bitrate; video pauses at 90 % of the free allowance and new calls stop at 99 %. Without Realtime keys (tests, development) the existing peer-to-peer mesh is used unchanged.

**Spec:** this document (design agreed with the owner on 2026-09-13: free only, no IP leaks, keep E2EE, phones first, do not break existing calls); prototype results in memory `voice-sfu-plan`.

## Global constraints

- Cloudflare Realtime API base `https://rtc.live.cloudflare.com/v1`; app secret and TURN token stay in chatd.env and are never sent to browsers. Send a `User-Agent` on every call (the API refuses some default agents) and no JSON body on `sessions/new`.
- Config: `REALTIME_APP_ID` + `REALTIME_APP_SECRET` (both or neither, else chatd refuses to start); `REALTIME_MONTHLY_GB` (default 1000). TURN keeps using `TURN_KEY_ID` + `TURN_API_TOKEN`.
- Frame format (both directions): `clear header | AES-GCM ciphertext+tag(16) | iv(12) | key index(1)`. Clear header = 1 byte for audio (Opus TOC), 10 bytes for a VP8 key frame, 3 for a VP8 delta frame; the header is the AES-GCM additional data. IV = 4-byte random per-sender salt + 8-byte big-endian counter. Video is VP8 only (setCodecPreferences).
- Voice frame key = HKDF-SHA256(conversation root, info `voice:<channelId>`, 32 bytes); key index = epoch & 0xff; senders use the latest epoch.
- Estimated egress rates: audio 64 kbps, screen audio 64 kbps, camera 1.5 Mbps (and the camera sender is capped at 1.5 Mbps in SFU mode), screen = the publisher's declared bitrate clamped to 1–12 Mbps. Screen tracks are pulled only while watched.
- Every task ends green on `go vet ./... && go test ./...` (race for the final run) and `npx tsc --noEmit && npx vitest run` for touched web code; commits use the repository's attribution lines.

## Tasks

### Task 1: config and the Realtime API client
- [ ] `internal/config`: `RealtimeAppID`, `RealtimeAppSecret` (both-or-neither validation, like Turnstile), `RealtimeMonthlyGB int64` (positive, default 1000). Tests in `config_test.go` (defaults, both-or-neither refused, bad GB refused).
- [ ] `internal/realtime/client.go`: `type Client struct { AppID, Secret, Base string; HTTP *http.Client }`; `type SessionDescription struct { SDP, Type string }` (json `sdp`, `type`); `type Track struct { Location, Mid, SessionID, TrackName, Kind, ErrorCode, ErrorDescription string }` (json camelCase as the API: `location, mid, sessionId, trackName, kind, errorCode, errorDescription`, all omitempty); methods `NewSession(ctx) (string, error)`, `AddTracks(ctx, session string, offer *SessionDescription, tracks []Track) (*TracksResult, error)` with `TracksResult { Description *SessionDescription; Renegotiate bool; Tracks []Track }`, `Renegotiate(ctx, session string, d SessionDescription) (*SessionDescription, error)`, `CloseTracks(ctx, session string, mids []string, offer *SessionDescription, force bool) (*TracksResult, error)`, `SessionTracks(ctx, session) ([]Track, error)`, `CloseSession(ctx, session) error` (lists tracks, force-closes every mid; a missing session is not an error). Non-2xx or a top-level `errorCode` → `*Error{Status, Code, Description}`. 10 s timeout.
- [ ] `client_test.go` against an httptest stand-in: bearer header and User-Agent sent, paths, no body on sessions/new, error mapping, CloseSession closes every mid with force.

- [ ] `internal/realtime/meter.go`: `type Meter struct` with an injectable clock; `Start(session, mid, kind string, bps int64)`, `Stop(session, mid string)`, `StopSession(session string)`, `Flush(ctx) error` (accrues elapsed×bps/8 for running pulls into the store under the current UTC month, resetting their start), `Used(ctx) int64` (cached, reloaded when the month changes), `VideoAllowed(ctx) bool` (< 90 % of limit), `CallsAllowed(ctx) bool` (< 99 %). `RateFor(kind string, declaredScreenBps int64) int64` implements the global rates. ### Task 3: voice registry and SFU endpoints
- [ ] `voice.State` gains `SFUSession string` and `Tracks voice.Tracks` (struct `{Audio, Video, Screen, ScreenAudio string}`, copy-safe) plus `ScreenBps int64`, all `json:"-"`; `voiceStatePayload` gains `media []string` listing published kinds (`audio`, `video`, `screen`, `screen_audio`). Registry gets `SetSFU(uid, connSession, session string) (old string, ok bool)` and `SetTrack(uid, session, kind, name string, screenBps int64) (State, bool)` that only act when the state's SFU session matches.
- [ ] Routes (authed, per-user limiter 240/min): `POST /api/v1/voice/sfu/session` → `{session_id}`; `POST /api/v1/voice/sfu/publish` `{session_id, offer, tracks:[{mid, kind, bitrate?}]}` → `{answer}`; `POST /api/v1/voice/sfu/subscribe` `{session_id, tracks:[{user_id, kind}]}` → `{offer?, renegotiate, tracks:[{mid, user_id, kind, error?}]}`; `PUT /api/v1/voice/sfu/renegotiate` `{session_id, description}` → `{description?}`; `PUT /api/v1/voice/sfu/close` `{session_id, mids, offer?}` → `{answer?, renegotiate}`. All return 404 `sfu_off` without keys.
- [ ] Authorisation: the caller has a voice state whose gateway session equals the request's auth session; publish/subscribe/renegotiate/close require `session_id == state.SFUSession`; subscribe only to users in the same channel whose state has that kind published; kinds are exactly the four above; video kinds refused with 403 `video_paused` when the meter says so; `canJoinVoice` refuses with `calls_paused` when calls are not allowed.
- [ ] Track names are made by the server (`<userId>-<kind>-<random>`); a successful publish records the name and rebroadcasts the voice state; subscribe starts meter pulls per returned mid; close stops them.
- [ ] Cleanup: any time a state leaves (hang-up, LeaveConn on socket close, moderator disconnect, kick/ban `dropVoice`, channel/server deletion) or its SFU session is replaced, stop its meter pulls and `CloseSession` in the background (5 s timeout). A moderator move closes the moved member's session too (their client makes a new one).
- [ ] `/voice/ice` adds `"sfu": true` when configured; admin stats add `realtime: {month, used_bytes, limit_bytes, video_paused, calls_paused}`.
- [ ] Tests (stand-in Realtime API): session needs voice membership and the same device; publish records tracks and adds `media` to the broadcast; subscribe to someone in another channel → 403, to an unpublished kind → 403, to a same-channel peer → 200 with mids; video paused → 403; hang-up and kick call CloseSession; replacing a session closes the old one; `sfu_off` without keys.

### Task 5: the SFU transport
- [ ] `web/src/api/voice.ts`: `sfuSession, sfuPublish, sfuSubscribe, sfuRenegotiate, sfuClose` matching Task 3; `ice()` returns `sfu?: boolean`.
- [ ] `web/src/voice/sfu.ts`: `class SfuTransport implements VoiceTransport`. One RTCPeerConnection (`bundlePolicy: "max-bundle"`, the ICE servers from `/voice/ice`, `encodedInsertableStreams` only for the legacy API); every SDP step runs on one promise chain. Audio transceiver published at start (sendonly, E2EE sender); camera and screen transceivers published the first time they are used and later only `replaceTrack`ed (VP8 preferred, camera capped at 1.5 Mbps, screen at its quality's bitrate); screen audio published when the share has audio. `setRoster` and `setWatching` compute the wanted subscriptions (audio and video of everyone else in the call who publishes them; screen and screen audio only while watched), then subscribe the new ones in one exchange (server offer → answer → renegotiate) and close the dropped ones in one exchange (stop transceivers → offer → close → answer). `ontrack` looks up the mid, protects the receiver, and reports `onRemoteStream(user, kind, stream)` (voice audio goes to Playback, screen audio too). Peer states mirror the connection state for every peer in the roster. A connection that is disconnected or failed for 5 s restarts ICE through renegotiate (offer with `iceRestart`), up to 3 times, then the whole session is rebuilt (new session, republish, resubscribe). Keys come from `voiceKeysFor` and are refreshed when the key ring changes.
- [ ] `session.ts`: pick `SfuTransport` when `ice.sfu` and `FrameCrypto.supported()`, else show "This browser cannot make encrypted calls; update it to join." when sfu is on; mesh otherwise. Pass rosters on every voice state for the call's channel; rebuild the transport on a moderator move. Handle `video_paused` / `calls_paused` errors with toasts, turning the camera or share back off.
- [ ] Browser check (scratch script, real Realtime app, local chatd): two users in a server voice channel hear each other (inbound audio energy), camera video decodes, screen share is pulled only after watching and dropped after unwatching, a third user in another channel cannot subscribe (API 403), relay-only ICE still connects, a phone viewport works, and the page never contacts another user's IP (remote candidates are Cloudflare's).
